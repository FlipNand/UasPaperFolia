# Verification environment

This directory holds the record of the real-server verification described in
[`wiki/Verification.md`](../wiki/Verification.md).

## What is kept

- `evidence/paper-26.3-169.log`, `evidence/folia-26.2-7.log` — the **complete** startup and
  `/uas status` output from both servers, including the injection trace. This is the primary
  evidence; everything quoted in the wiki comes from here.
- `paper/` and `folia/` — server directories ready to run, minus the server jars and the
  downloaded runtime (see below).
- `paper/run-paper.sh`, `folia/run-folia.sh` — launchers.

Their console is a FIFO, so commands can be injected into a running server without a TTY:

```bash
cd verify/paper
./run-paper.sh > server.log 2>&1 &     # or run it in its own terminal
printf 'uas status\n' > console.in     # then, from anywhere
```

`run-paper.sh` opens the FIFO with `exec 9<>console.in` before exec'ing Java, and that is the
whole trick. Opening a FIFO `O_RDWR` never blocks and holds a writer for the script's lifetime,
so Java sees a stdin that can block on read but never reports EOF — which is how a real console
behaves. Opening it `O_WRONLY` instead deadlocks: the shell would block waiting for a reader
that cannot start until the shell proceeds.

## What was removed

The downloaded server jars, `libraries/`, `cache/`, `versions/` and the generated `world/`
directories accounted for roughly 450 MB and are re-downloadable, so they were deleted. The
server directories were left in place, so re-running needs only the jar and the first startup
will fetch the rest itself.

Both server jars came from the PaperMC fill v3 API and were checksum-verified:

| Server | Version | Jar |
| --- | --- | --- |
| Paper | 26.3 build 169 | `185d9f4267afca48959d6a56150cf8803b6645aee10de3ed147df7ab1ff781fb` |
| Folia | 26.2 build 7 | `128a634192261cd38bb4a5dc54075018a0f896fd6c6f529e37dca6e99e32b3b3` |

```bash
# resolve the current build numbers
curl -s https://fill.papermc.io/v3/projects/paper/versions/26.3/builds | head -c 400
```

## Reinstalling the plugin after a build

```bash
./gradlew build
cp dist/uas-example-1.0.0.jar verify/paper/plugins/
cp dist/uas-example-1.0.0.jar verify/folia/plugins/
```

Delete `plugins/UASExample/config.yml` to see the out-of-the-box defaults again — useful,
because an existing config generated by an older build keeps its old `public-base-url`.

## End-to-end checks

```bash
# pack over the game port, on both servers
curl -I   http://127.0.0.1:25565/uas/pack/uas-example   # Paper
curl -I   http://127.0.0.1:25566/uas/pack/uas-example   # Folia

# the packs must be byte-identical (see wiki/Verification.md)
curl -s http://127.0.0.1:25565/uas/pack/uas-example | shasum -a 1
curl -s http://127.0.0.1:25566/uas/pack/uas-example | shasum -a 1

# a Minecraft status handshake on the same port
# (full script in wiki/Getting-Started.md)
python3 ping.py 25565
python3 ping.py 25566
```

Expected pack hash for this revision: `49624535ef0032b28e824e263bdbd625ae0df67d`, 2106 bytes.

## Ports

Paper is on **25565** and Folia on **25566**, chosen on purpose: running them on different ports
is what exposed the hardcoded `public-base-url` default, and running different Minecraft
versions is what exposed the pack's non-determinism.
